1The reproducibility ladder

"Deterministic" means the same input always gives the same output. Three common ways to classify text sit at very different points on that scale.

DeterministicKeyword and scoring rules
  • Same text + same table version = same label
  • Every label points to the words that caused it
  • Only recognises wording you anticipated
Reproducible once frozenTrained classifier
  • TF-IDF + logistic regression, fixed seed, saved model
  • Same input + same model version = same label
  • Less explainable; accuracy must be measured
Not guaranteedLLM prompt
  • "Classify this against my table"
  • Can differ between runs, users and model updates
  • Microsoft's own docs say generative answers aren't deterministic
The design rule used on this pageAn AI may help you build the keyword table or write the code. Whatever runs on your complaints must be rules or a frozen model, so a re-run gives the same result and every label records which version produced it.

4Worked example in Python in Excel

Eight cells, run in order. Each has a copy button and the real output from my test run.

Set up the workbook

  1. Download the two CSVs above. In Excel use Data → From Text/CSV to load each onto its own sheet.
  2. Click inside each dataset, press Ctrl+T to make it a table, then rename the tables on the Table Design tab: Complaints and Rules.
  3. On a new sheet, click a cell, then Formulas → Insert Python (or type =PY(), paste cell 1, and press Ctrl+Enter.
  4. Paste each next cell into the next cell below. Python in Excel runs cells row by row, top to bottom, so order matters and later cells reuse earlier variables.
  5. For cells that return a table, set the output to Excel Value to see the grid.
Before using real complaintsPython in Excel runs calculations in Microsoft's cloud. Check with your information security or data protection team that your real complaint data is allowed there. Practise with this synthetic data first.

5What the test run showed

I ran this exact code on the dataset above (scikit-learn 1.9.1, seed 42). Python in Excel may use different library versions, so small differences are possible.

5 of 5retrains gave an identical fingerprint
89%of held-out test complaints auto-labelled correctly
8%sent to a human review queue

What this tells you

  • Reproducibility is real. The fingerprint covers every prediction and probability for all 900 rows. Five separate trainings produced the same one.
  • My first-draft keyword rules were the weakest part: about 83% accurate where they fired, and they only fired on about a third of test complaints. The model did better (about 93% on the rows it labelled). That is normal for a first draft, and why the table needs improving from the unclassified and wrong-label pile.
  • Consistent is not the same as correct. A frozen model can be reproducibly wrong. Reproducibility lets you measure the error and fix it deliberately.
  • The review queue earns its place. Low-confidence complaints go to a person instead of being forced into a label.

6What "frozen" means

Frozen means the process uses a fixed trained model and never quietly retrains.

In Python in Excel

There is no file system, so the model is rebuilt from the same data, the same seed and the same settings each time the workbook calculates. That is reproducible, but only while the data, settings and library versions stay the same. Treat the data table and MODEL_VERSION as the frozen artefact, and re-check the fingerprint (cell 6) after any change.

In ordinary Python (stronger)

Train once, save the model with joblib, and have the live process only load it. The downloadable script does this and writes a small metadata file.

One thing I found while testing: the saved file's hash differed between two identical training runs, even though every prediction was identical. So use the prediction fingerprint to prove two models behave the same, and the file hash to prove a particular saved file hasn't been swapped.

Store this with every label

Label, method (rule, model or human queue), confidence or score, matched keywords, version, and date. With that, any classification can be explained and re-created later.

7Making the case

What you can say accurately, and what to avoid.

Safe to say
"Microsoft's Copilot Studio documentation states that generative answers aren't deterministic, so identical runs aren't guaranteed to match. We can measure how much ours varies with a repeat-run test."
Safe to say
"A keyword and scoring table, or a frozen trained model, gives the same result every run, and we can prove it with a fingerprint."
Avoid
"Copilot is always wrong / always inconsistent." Often it agrees with itself; the point is that nothing guarantees it.Also avoid claiming Microsoft says this about a specific product or task unless you have found that exact page.

A five-minute demonstration

  1. Take 50 to 100 borderline complaints from your real data.
  2. Have five people (or one person five times) run the LLM prompt on them. Compare labels row by row and report the agreement rate.
  3. Run cell 6 five times and show the identical fingerprint for the model route.
